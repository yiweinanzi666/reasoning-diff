## 五、必须保住的科学正确性

2. **完整域适配。** GSM-Symbolic、GSM-Plus、HotpotQA、MuSiQue 和 HumanEval 路径都有读取、合法编辑、更新后真值、事件/独立标注接入和域内评分。T4 保存策略变化、信息不足、矛盾、无解等区别。外部缺失的标注资产不能凭空生成；实现实际导入、验证和使用流程，并列明所需资产。

8. **校准。** 对完整轨迹/序列或声明的问题块取最大分数，采用精确有限样本顺序统计量及超出样本数时的无穷阈值。经验标签覆盖、未知标签、真正空真集与全真实依赖覆盖分开；不得把同题重复当独立样本扩大 N。

10. **前瞻干预。** 来源—数值解耦、高层响应矩阵、donor/base 对齐、同值/异值条件、位置平衡等在执行前声明。swap、选择性消融/INLP、rescue 与错误来源/随机救援有实质实现；hook 层内位置和 KV 更新范围正确，条件间缓存隔离，异常后 hook 清理。
11. **必做对照。** C-rand/C-layer 与主干预属于同一预定 cohort，C-layer 在开发集选择，实际范数/秩/位置/随机流匹配。每组报告目标、非目标、任务正确、无效输出和失败；相对两对照的差值才承担主效应。
12. **C3 统计。** P1 使用留出预测并比较链长+op 基线的增量；P2 使用配对 no-op，处理新增前提改变分母；P3 检验相对对照的恢复。问题级聚类、不确定性、选择偏差、单类/小样本与缺失数据有明确处理。未检出 P3 不能推出“虚假依赖只是后果”。
13. **附录功能。** 无门控修复、Oracle/行为参考/探针/文本/随机/截断/提示/检索/全重推、公平原始 token 预算、连续编辑、离线逐步/最终评分、失效分类和成本分别实现。保留文本在新前缀重新 Prefill；验证器不能触发运行时 fallback 或删除失败。原文中的几何/锥传播/相似度等附录项目也须逐项登记和落实适用实现。
14. **边界与结论。** 单点扫描不证明任意联合编辑 soundness；可解码不独自证明“已经决定”。Gate 未注册时没有 pass/fail；Week-8 能表示未运行、数据不足、协议无效、未注册及正式检验结果。不得把预期数值、fixture 或随机模型输出写入真实科学结论。
15. **代码任务。** 生成代码与测试仅通过显式隔离执行器；超时、资源限制、无可用执行器、异常输出可报告，不回退宿主 exec。普通 subprocess 或 HumanEval reliability_guard 不能冒称隔离沙箱。

| 通道 | 独立任务 |
|---|---|
| A：原文一致性 | 直接读原论文及确认后的协议，检查所有段落/公式/表格/附录要求到需求、实现和证据的映射；主动找遗漏、降级实现和偷换概念 |
| B：数据与测量 | 查 T1–T4 适配、编辑有效性、独立真值、事件身份、结构变化、有限扫描、噪声机会、标签分母与划分泄漏 |
| C：数学与统计 | 独立推导探针、校准、迁移映射、P1–P3、区间、预算与成本公式，用边界和反例查错 |
| D：模型与因果 | 查 token/前缀、thinking 模板、采样状态、hook/KV、donor 来源、swap/ablation/rescue、两类控制及非目标/无效输出 |

分工只是重点，不是禁止发现其他问题。向 reviewer 提供原始材料、要求、固定代码版本和审查范围；首轮不要提供作者“应该已正确”的结论，也不要给其他通道的通过结论来诱导一致。审查完成后再汇总和交叉质询。

审查通道默认只读，报告写入各自文件；不要让多个 reviewer 同时改同一生产文件。若委派修复，明确文件所有权，告知每个 worker 仓库有人并行工作、不得覆盖或回滚他人改动。

## 八、修复—复审必须形成闭环

汇总所有通道到统一 ISSUES 清单并去重，保留发现来源。每个问题按“发现 → 复现/论证 → 修复 → 回归 → 独立复核”流转。

所有已确认且在范围内的正确性、科学一致性、可靠性、数据完整性和必要功能缺陷都要解决，不能只修 Critical 后忽略 Warning。单纯风格偏好和范围外增强可以不实现，但须说明为何不影响要求；争议项由独立 reviewer 用源码/复现证据裁定，不能由作者自行删掉。

禁止通过以下方式达到表面清零：降低严重度、未经依据标为误报、接受本可修的风险、删除原要求/样本、改测试期待以迎合错误实现、添加无理由 skip、把软件问题改名为 GPU 问题，或扩大 unknown 来提高指标。

修复后先运行对应复现与受影响回归，再复核调用链和原文。审查期间代码发生变化时，旧版本的通过意见不能直接覆盖新代码；注明受影响范围，最后仍需对最终代码完成全量验收。

同一问题反复出现或修复引入循环时，重新建立最小复现并检查上游协议/接口设计，必要时补充或修订 GSD 计划，再继续修复。不要用不断改文档掩盖实现缺陷，也不要无限重复没有新证据的命令。

## 九、停止条件：全部满足才可宣布代码交付完成

完成不取决于跑了多少轮，而取决于以下证据全部满足：

1. 原论文及确认后的协议逐项有归属；全部代码范围的原子需求有真实实现、可到达入口和验证证据，追踪表不存在未解释的遗漏。
2. 无已确认未解决的范围内缺陷，无未裁定的可能影响正确性/论文要求的审查疑点；不能以实现者自称低风险跳过。
3. 所有适用于当前本机的必要检查实际运行通过；有意义的端到端路径、边界与失败路径被覆盖，未运行项没有伪装成通过。
4. 所有 GSD 阶段和补缺计划都有与实际状态一致的文档与证据，跨阶段集成完成。软件通过与服务器/科学待验证分别表示，不能把全部科学验收勾成完成。
5. **连续两轮独立的全量多路审查均未发现新的已确认缺陷，且所有既有缺陷已经独立复核关闭。** 两轮均覆盖 A–F，第二轮采用新 reviewer 上下文；两轮针对同一最终生产代码、配置和测试内容 hash。任一轮发现需改动代码/配置/测试的问题，修复后重新开始连续通过计数。只补充审查日志不改变被审代码 hash。
6. 服务器待验证项、外部真值/标注资产、Gate 未注册项全部列明所对应需求、已实现路径、未验收原因、将来命令与预期产物；缺失代码不能藏入这份清单。
7. 最终交付包含运行说明、配置与依赖说明、完整追踪表、问题闭环、审查报告、本机验证记录及服务器执行/验收入口。

最终允许的成功结论是：**在声明范围与本机验证条件下代码验收通过，独立多路审查未发现已确认遗留缺陷；真实模型/服务器科学验证仍待运行。** 这不等于形式证明所有输入和环境下绝对无错误，也不意味着论文假说成立。不要作超出证据的承诺。

真实 GPU 不可用不应使你无限等待或提前省略代码：完成所有独立可推进的实现与检查后，以 `CODE_READY_SERVER_VALIDATION_PENDING` 明确交付。若存在必须由用户提供且无法合理推导的关键输入，先完成不依赖它的工作，再记录具体阻塞并提出最小必要问题；此时使用 `BLOCKED_EXTERNAL`，不能宣布目标完成。未预注册科学阈值按既定 null 路径实现，不是停止写代码的理由。

上下文、额度、宿主或工具中断不是完成。持续保存 STATE、当前计划、问题清单、最后通过的验证版本和下一条恢复命令；恢复后重新核对工作区并继续，不从头重写、不遗忘未关闭问题。若真实 subagent 无法调用，明确报告该验收条件未满足，不能用自我复述替代独立审查。

## 十、最终回复应交付什么

最终给出：代码交付状态；原子需求覆盖表入口；实现与测试的具体证据；两轮 A–F 审查的版本和报告路径；全部问题关闭记录；服务器/数据资产/预注册待办及真实限制；在服务器开始执行所需的准确命令。

不要以“基本完成”“应该没问题”“后续可以继续优化”作为未闭合工作的结论。现在从读取项目状态、核对当前 GSD 能力和建立原文追踪表开始，随后持续执行到上述停止条件满足。
